# مساعد كراسة الشروط والمواصفات

**معهد البحوث والدراسات — جامعة الأمير مساعد بن عبدالرحمن — إدارة المشتريات والعقود**

هذه الحزمة تحتوي منصتين ويب، والخادم الذي يشغّلهما ويربطهما بالذكاء الاصطناعي، والقوالب والأمثلة المرجعية. هذا الملف موجّه للمبرمج الذي سيتولى المراجعة النهائية والرفع على السيرفر والربط مع الأنظمة.

| المنصة | المستخدم | المسار | ما تفعله |
|---|---|---|---|
| مساعد كراسة الشروط | مدير المشروع | `/` | يشرح المشروع بكلامه، فيصوغ المساعد الأجزاء الفنية: التعريف، والتقييم، ونطاق العمل، وجدول الكميات من دليل الأصناف. المخرج ملف Word يُرفع في ERP |
| إصدار كراسة الشروط | مدير العقود | `/contracts` | يرفع ملف مدير المشروع، ويكمل البيانات المتبقية، ثم يصدر الكراسة النهائية كاملة بنموذج المعهد المعتمد |

## 1. التشغيل السريع

### أ) خادم Node.js (موصى به للسيرفر الداخلي)
```bash
# Node 18 أو أحدث، ولا يحتاج أي مكتبات لتشغيل الخادم
cp server/node/.env.example server/node/.env      # ثم عبّئ القيم
npm run build                                     # يولّد dist/ وملف worker.js
npm start                                         # http://localhost:8080  و  /contracts
```
- خلف Nginx أو IIS: مرّر كل الطلبات إلى المنفذ `PORT`، وفعّل HTTPS.
- `npm run build` يجعل المكتبات تُحمَّل من `dist/vendor/` محليًا، فلا يحتاج المتصفح الوصول إلى CDN. الخطوط فقط من Google Fonts، ولها بدائل تلقائية إن لم تتوفر.

### ب) Cloudflare Workers (للعرض التجريبي)
1. `npm run build`
2. انسخ محتوى `server/cloudflare/worker.js` إلى Worker جديد.
3. أضف الأسرار `ANTHROPIC_API_KEY` و`ACCESS_CODE`، والمتغير الاختياري `MODEL`.

### ج) بدون ذكاء اصطناعي
افتح ملفات `dist/*.html` مباشرة أو من أي خادم ملفات ثابتة. كل الوظائف تعمل ما عدا المساعد الذكي: التعبئة، والتدقيق، والتصدير، والإصدار.

### متغيرات البيئة
| المتغير | إلزامي | الوصف |
|---|---|---|
| `ANTHROPIC_API_KEY` | نعم (للمساعد) | مفتاح Claude API. يبقى على الخادم ولا يصل للمتصفح |
| `ACCESS_CODE` | نعم (للمساعد) | رمز دخول مشترك يطلبه المساعد مرة واحدة ويُحفظ في المتصفح. **مؤقت؛ يُستبدل بـ SSO** (القسم 6) |
| `MODEL` | لا | الافتراضي `claude-sonnet-5-5` |
| `ANTHROPIC_BASE_URL` | لا | لتمرير الطلبات عبر بوابة معتمدة. الافتراضي `https://api.anthropic.com` |
| `PORT` | لا | الافتراضي 8080 (خادم Node فقط) |
| `RATE_PER_MIN` | لا | حد الطلبات لكل IP في الدقيقة، الافتراضي 20 (خادم Node فقط) |

## 2. بنية الملفات

```
src/project-manager.html     المصدر: صفحة مدير المشروع (ملف واحد: HTML + CSS + JS)
src/contract-manager.html    المصدر: صفحة مدير العقود (الكود نفسه + window.KURRASA_MODE="contracts")
build/build.mjs              يولّد dist/ و server/cloudflare/worker.js من src/
dist/                        الصفحات الجاهزة للنشر + vendor/ (يُعاد توليده؛ لا يُعدَّل يدويًا)
server/node/server.mjs       خادم Node: يقدّم الصفحات ويمرّر طلبات الذكاء الاصطناعي
server/cloudflare/           worker.template.js (المصدر) و worker.js (مولَّد)
vendor/                      docx 8.5.0 و JSZip 3.10.2 (رخصة MIT)
data/catalog_erp.json        دليل الأصناف من ERP (1407 صنفًا مكوّدًا) — مضمَّن في الصفحة
data/Wh_Items_SP_*.xlsx      ملف التصدير الأصلي من ERP
data/logo-full*.png          الشعار الكامل للجامعة والمعهد (مضمَّن في الصفحة: LOGO_FULL_B64 — غلاف الكراسة)
data/logo-symbol.png         رمز الشعار (مضمَّن: LOGO_B64 — رأس الصفحة وملفات Word)
reference/templates/         النماذج الأصلية التي بُنيت عليها الأداة
reference/samples/           أمثلة على مخرجات الأداة (ملفات Word)
tests/e2e.mjs                اختبار شامل (القسم 8)
```

> **ملاحظة مهمة:** ملفا `src/` كُتبا أصلًا كصفحات Claude Artifacts، لذلك يبدآن مباشرة بـ `<title>` و`<style>` دون `<!doctype>`. سكربت البناء يغلّفهما بمستند HTML كامل. **عدّل في `src/` ثم شغّل `npm run build`.**
>
> الصفحتان تشتركان في الكود نفسه، والفرق سطر `window.KURRASA_MODE`. أي تعديل يجب أن يُطبَّق على الملفين، أو ولّد الثاني من الأول (القسم 9).

## 3. المسار الوظيفي

```
مدير المشروع (/)
  ├─ «اشرح مشروعك»: المساعد يفهم، ويسأل، ثم يكتب مسودة كاملة
  ├─ مراجعة الخطوات: البيانات، والتعريف، والاتفاقية الإطارية، والتقييم، والنطاق، والكميات
  ├─ تدقيق آلي: الحقول الإلزامية، وضوابط الأوزان، والعبارات المبهمة، والتداخل، ودليل الأصناف
  └─ تصدير Word (يحمل خصائص مخصصة + جدول «ترميز الأصناف»)  ←  يُرفع في ERP
                                                               ↓
مدير العقود (/contracts)
  ├─ رفع ملف Word: قراءة الأقسام حسب عناوينها، والبنود، والأكواد
  ├─ إكمال البيانات: المواعيد، والممثل، والمدد، والغرامات، والكميات، والتدريب
  ├─ تدقيق: الحقول المظللة، والحدود النظامية، والأصناف الجديدة + مراجعة اختيارية بالذكاء الاصطناعي
  └─ إصدار الكراسة النهائية (Word) بنموذج المنافسة العامة أو نموذج الاتفاقية الإطارية المعتمد
```

## 4. البنية التقنية

### 4.1 التخزين
لا توجد قاعدة بيانات. كل البيانات في `localStorage` على جهاز المستخدم:
| المفتاح | المحتوى |
|---|---|
| `kurrasa-draft-v1` | مسودة مدير المشروع (كائن `S`) |
| `kurrasa-cm-v1` | بيانات مدير العقود (كائن `K`)، ومنها الملف المقروء والإعدادات الافتراضية |
| `kurrasa-access-code` | رمز الدخول للمساعد (وضع الخادم فقط) |

يمكن حفظ المسودة كملف JSON وفتحها لاحقًا من أزرار «حفظ المسودة» و«فتح مسودة».

### 4.2 الذكاء الاصطناعي
الصفحة تختار مزوّد الذكاء الاصطناعي تلقائيًا:
1. **داخل Claude.ai (Artifact):** تستخدم `window.claude.use("sample")` بحساب المستخدم نفسه.
2. **على خادمكم:** إذا عُرّف `window.KURRASA_API`، وهو ما يضيفه سكربت البناء، تستخدم `makeProxyAI()` الذي يرسل:
   ```
   POST /api/claude
   headers: x-access-code: <الرمز>
   body:    {"messages":[{"role":"user","content":"..."}], "tier":"default|complex"}
   →        {"text":"...", "stop_reason":"end_turn"}
   ```
   الأخطاء: `401` رمز خاطئ، `429` تجاوز الحد، `502` خطأ من المزوّد.
3. **غير ذلك:** يُعطَّل المساعد، وتعمل بقية الأداة دونه.

**الضوابط المضمّنة في الطلبات:**
- **المرجع النظامي:** كل طلب يحمل التعليمات من `rules()`، ومعها نص «المرجع المعتمد» من `REF`.
- **حذف الإحالات غير الموجودة:** أي إحالة يذكرها النموذج لمادة غير موجودة في `REF` تُحذف قبل العرض (`legalHTML` و`linkRefs`).
- **سرية التكلفة التقديرية:** مبلغ الميزانية لا يُرسَل للنموذج إطلاقًا. يُرسَل فقط هل هو أقل من 25 مليون ريال أو أعلى (`budgetBand()`)، التزامًا بسرية التكلفة التقديرية (المادة 23).
- **المسودات:** كل مخرج من الذكاء الاصطناعي يبقى مسودة، ولا يدخل الحقول إلا بضغطة «اعتماد» من المستخدم.

### 4.3 ملفات Word
- **الإنشاء:** مكتبة `docx` (UMD، المتغير العام `docx`)، باتجاه عربي (`bidirectional` و`rightToLeft` و`visuallyRightToLeft`) وخط `Frutiger LT Arabic` المعتمد في نماذج المعهد.
- **خصائص ملف مدير المشروع:** يحمل خصائص مخصصة في `docProps/custom.xml`: `KurrasaVersion` و`KurrasaRegime` و`KurrasaType` و`KurrasaFwKind`.
- **قراءة الملف في صفحة مدير العقود:** تتم في `readPmDocx()` عبر JSZip وDOMParser، بالاعتماد على **عناوين الأقسام**. لا تغيّر هذه العناوين في `compose()` دون تعديل `HEADS`:
  `اسم المنافسة` · `تعريف عن المنافسة` · `مدة الاتفاقية الإطارية` · `طبيعة الاتفاقية الإطارية` · `معايير تقييم العروض` · `نطاق العمل` · `جدول الكميات` · `ترميز الأصناف`
- **نقل الأقسام إلى الكراسة:** تُنقل كما هي على مستوى XML (`w:p` و`w:tbl`) إلى الكراسة النهائية، فتبقى أي تعديلات أجراها مدير المشروع في Word. التفاصيل في `buildBookletDocx()`، التي تستبدل فقرات علامات `§§key§§`.
- **ما لا يدخل الكراسة:** جدول «ترميز الأصناف» وجدول بيانات مدير المشروع (الذي فيه الميزانية).

### 4.4 دليل الأصناف
- **الدليل الحالي:** `CATALOG` مضمَّن في الصفحة من `data/catalog_erp.json` (تصدير ERP بتاريخ 28/5/1448هـ، 1407 أصناف). الحقول: `{code, name, unit, group}`، والمعرّف `id` هو الكود.
- **المطابقة:** بحث عربي مطبَّع في `normAr()` و`arToks()` و`catalogSearch()`، يتعامل مع الهمزات والتاء المربوطة و«ال» والسوابق، ويقيس التشابه بالكلمات المشتركة وبثلاثيات الأحرف.
- **البند المرتبط بالدليل:** يُثبَّت اسمه ووحدته وكوده. البند غير المكوّد يتطلب مبرر «صنف جديد»، ويُمنع إذا كان يشبه صنفًا مكوّدًا (التشابه ≥ `SIMILAR_T` = 0.6) ما لم يؤكد المستخدم أنه مختلف. تكرار الصنف (بالكود أو بالاسم) ممنوع.
- **أسماء مكررة داخل ERP:** يوجد 99 اسمًا بأكثر من كود (`CAT_SAME`)؛ تنبّه الأداة عند اختيار أحدها.
- **فحص التداخل:** `scopeAnalysis()` يجد المهام المتشابهة، وبنود الكميات المتقاربة، والمهام بلا بنود، والبنود بلا مهام. معه زر فحص بالذكاء الاصطناعي.

### 4.5 النصوص الثابتة للكراسة
- `BK`: نموذج المنافسة العامة، منقول من `reference/templates/كراسة منافسة عامة صادرة.pdf` مع تصحيحات طفيفة موثّقة.
- `BK_FW`: نموذج الاتفاقية الإطارية **المعتمد**، منقول نصًّا من `reference/templates/نموذج كراسة الاتفاقية الإطارية المعتمد.docx`.
- **القيم المتغيرة** تُكتب داخل النص هكذا: `{validityTxt}` و`{delayCap}` و`{trainingTxt}`، وتُستبدل في `kTxt()`.
- **الإحالات الداخلية** تُكتب هكذا: `{#elig}` و`{#techdocs}`، وتُحسب أرقامها تلقائيًا.

## 6. نقاط الربط المقترحة مع الأنظمة

| الربط | الوضع الحالي | المقترح |
|---|---|---|
| **دليل الأصناف (ERP)** | قائمة مضمّنة في الصفحة (تحديثها يدويًا بإعادة البناء) | نقطة `GET /api/catalog` تقرأ من ERP بالحقول `{code,name,unit,group,desc}`، وعند التحميل: `CATALOG.splice(0, CATALOG.length, ...data)` ثم إعادة بناء الفهارس (`_n` و`_t` و`_g` و`_d`) و`CAT_BY`. الكود المرتبط ببنود الكميات جاهز ويُنقل لمدير العقود |
| **الهوية (SSO / Active Directory)** | رمز دخول مشترك `ACCESS_CODE` | التحقق من الجلسة في `/api/claude` بدل الرمز. وفصل الصلاحيات: `/contracts` لفريق العقود فقط |
| **رفع ملف مدير المشروع في ERP** | يدوي | إرسال الملف المصدَّر (و/أو كائن `S` بصيغة JSON) إلى ERP مباشرة من زر التصدير |
| **التخزين المركزي** | `localStorage` | حفظ المسودات والكراسات المصدرة على الخادم، مع سجل تدقيق (من اعتمد مخرج الذكاء الاصطناعي ومتى) |
| **سجل الاستخدام** | لا يوجد | تسجيل عدد الطلبات وزمنها **دون محتوى الطلبات** في `server.mjs` |
| **منصة اعتماد / لوجكس** | لا يوجد | رقم المنافسة، ونقل بنود الكميات |

## 7. الأمن والخصوصية: قائمة مراجعة قبل الإطلاق

- [ ] **موافقة الأمن السيبراني:** موافقة الجهة المختصة بالجامعة على تصنيف بيانات المنافسات واستخدام خدمة ذكاء اصطناعي خارجية لها (أو تمريرها عبر `ANTHROPIC_BASE_URL` لبوابة معتمدة).
- [ ] **سرية الإعدادات:** ملف `.env` خارج Git، والمفتاح في مخزن أسرار.
- [ ] **HTTPS** إلزامي.
- [ ] **الهوية:** استبدال `ACCESS_CODE` بـ SSO، وتقييد `/contracts`.
- [ ] **ترويسة CSP:** مقترح:
  `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'`
  > الكود يستخدم سكربتات وأنماطًا مضمّنة (inline)، ولهذا يلزم `unsafe-inline`. نقلها إلى ملفات مستقلة خيار لاحق.
- [ ] **حد الطلبات:** مراجعة الحد في `server.mjs`، فهو بسيط في الذاكرة. استبدله بـ Redis أو بإعدادات البوابة عند تعدد الخوادم.
- [ ] **سرية التكلفة التقديرية:** التأكد من عدم إرسالها لأي خدمة خارجية. الحالة الحالية مُتحقق منها: `budgetBand()`.
- [ ] **سجلات الخادم:** التأكد أنها لا تحفظ محتوى الطلبات.

## 9. ملاحظات للمراجعة الفنية

- **حجم الملفين:** كل ملف ~500KB بسبب الشعار المضمّن (base64) ودليل الأصناف. يمكن نقلهما لملفات مستقلة.
- **الكود مكرر في الملفين:** الأفضل جعل `contract-manager.html` يُولَّد من الأول في `build.mjs` بإضافة سطر `KURRASA_MODE`، أو تقسيم JS إلى وحدات.
- **فحص التداخل الآلي** يعتمد على التشابه اللفظي، والعتبات في `scopeAnalysis()`، فقد يفوته تداخل بكلمات مختلفة. لذلك يوجد بجانبه فحص بالذكاء الاصطناعي.
- **المرجع النظامي `REF`** ملخصات أمينة لمضمون المواد بأرقامها، وليس النص الرسمي حرفيًا. بعض مواد لائحة 1440 الخاصة بالاتفاقيات الإطارية من مصدر ثانوي، ومعلَّمة داخل الأداة. يُستحسن استبدالها بالنص الرسمي بعد مراجعة الإدارة القانونية.
- **نظام 1448:** النصوص الثابتة (`BK` و`BK_FW`) مبنية على نظام 1440. الأداة تمنع الإصدار النهائي لمنافسة تخضع لنظام 1448، الذي يبدأ نفاذه مطلع يناير 2027 تقريبًا، حتى تُحدَّث النصوص.
- **الاعتماد على الإنترنت:** الخطوط من Google Fonts فقط. لبيئة معزولة تمامًا، نزّل الخطوط وضعها في `dist/` وعدّل وسم `<link>`.
- **ملاحظات في نموذج الاتفاقية الإطارية المعتمد تُركت كما هي** بانتظار قرار الإدارة القانونية:
  - بقايا كلمة «الجهة».
  - تذكير وتأنيث «المعهد».
